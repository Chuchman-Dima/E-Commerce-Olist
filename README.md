# Olist E-Commerce: аналіз замовлень бразильського маркетплейсу

Аналітичний проєкт на відкритому датасеті [Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce): ~100 тисяч замовлень за 2016-2018 роки.

**Головне питання проєкту:** як затримка доставки впливає на оцінки клієнтів і що з цим може зробити бізнес?

**Стек:** PostgreSQL, SQL (JOIN, GROUP BY, CASE, підзапити), Python (pandas, matplotlib), Power BI.

## Ключові висновки

| Показник | Результат |
|---|---|
| Обсяг даних | 99 441 замовлення, 96 096 унікальних клієнтів, період 2016-09 ... 2018-10 |
| Доставлені замовлення | 97% (96 478 з 99 441), скасовані лише 0,6% |
| Ріст бізнесу | замовлень на місяць у 8 разів, виручка у 7 разів (2017-01 → 2018-08); пік у листопаді 2017 (7 421 замовлення) |
| Найбільші категорії | health_beauty, watches_gifts, bed_bath_table = 26,1% виручки; топ-10 = 62,9% |
| Географія | штати SP, RJ, MG = 66,5% замовлень |
| Доставка | в середньому 12,5 дня; товар приходить на 11,9 дня раніше обіцяного; запізнюється 6,8% замовлень |
| Оцінка при доставці вчасно | 4,29 |
| Оцінка при затримці 1-3 дні / 4-7 днів / понад 7 днів | 3,29 / 2,11 / 1,70 |
| Частка поганих оцінок (1-2) | 9,2% при доставці вчасно проти 62,4% із запізненням |
| Штати з найбільшою часткою запізнень | MA 17,4%, CE 13,8%, BA 12,2%, RJ 12,1% |
| Повторні покупці | 3,04% клієнтів |

### Що це означає для бізнесу

1. **Точність термінів важливіша за швидкість.** Товар у середньому приходить раніше обіцяного, але запізнення різко знижує оцінку: з 4,29 до 1,70 при затримці понад тиждень.
2. **Проблемні регіони.** У штатах MA, CE, BA та RJ запізнень найбільше. Варто реалістичніше розраховувати там терміни доставки.
3. **Утримання клієнтів.** Майже 97% клієнтів купують один раз, тож найбільший потенціал росту в повторних покупках.

## Правила розрахунків

Однакові в SQL, ноутбуці й Power BI (докладно в `sql/05_build_analytics_tables.sql`):

- **Валідне замовлення:** не `canceled`, не `unavailable`, має хоча б одну позицію.
- **Виручка:** ціна товарів без доставки. `payment_value` для виручки не використовується, бо містить доставку і відсотки за розстрочку.
- **Оцінка замовлення:** округлене середнє його відгуків (деякі замовлення мають кілька відгуків).
- **Затримка:** різниця дат (без часу) між фактичною та обіцяною датою доставки; `delay_days > 0` означає запізнення. Аналізується лише для доставлених замовлень з датою доставки.
- **Період динаміки:** 2017-01 ... 2018-08, бо вересень-грудень 2016 і вересень-жовтень 2018 неповні.

## Якість даних

- `order_id` унікальний. Пропуски дат доставки відповідають недоставленим і скасованим замовленням.
- `customer_id` створюється на кожне замовлення (99 441), реальних клієнтів 96 096, тому повторні покупки рахуються за `customer_unique_id`.
- Є замовлення з кількома відгуками, тому оцінка зводиться до одного значення на замовлення.
- Частина товарів без категорії або без перекладу категорії позначена як `unknown` (використовується `LEFT JOIN`, щоб не губити їх).

## Обмеження

- Немає даних про маркетингові витрати і маржу.
- Оцінки є не для всіх замовлень, а зв'язок «затримка → оцінка» є кореляцією, а не доведеною причиною.
